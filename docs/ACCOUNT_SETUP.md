# Подключение настоящих аккаунтов GPT Build Lab

## Важно: публичный сайт можно оставить публичным

GitHub Pages продолжает раздавать HTML/CSS/JS всем посетителям. Supabase отдельно отвечает за регистрацию, вход и хранение профилей. Публичность сайта не делает таблицы пользователей публичными: доступ к профилям ограничивает Row Level Security (RLS).

## Что уже подготовлено в репозитории

- `web/auth.html` — формы входа и регистрации; регистрация вызывает серверную Edge Function, а вход выполняется через Supabase Auth.
- `web/supabase-config.js` — публичная конфигурация клиента, пока с заглушками.
- `web/index.html` — проверка сессии, имя пользователя в меню аккаунта, выход и сохранение аватара в профиле.
- `supabase/migrations/202611210002_username_accounts.sql` — таблица профилей, уникальные имена пользователей, триггер создания профиля и RLS.\n- `supabase/functions/username-signup/index.ts` — серверная регистрация без отправки email.\n- `supabase/migrations/202611220001_signup_rate_limit.sql` — ограничение публичной регистрации до 5 попыток в час с одного IP.
- Пароли не попадают в таблицу `profiles` и не сохраняются в localStorage. Их обрабатывает Supabase Auth.

## Как работает вход по имени пользователя

Supabase Auth хранит учётную запись в формате email/password, но пользователь вводит только имя и пароль. Интерфейс формирует внутренний адрес `username@gptbuildlab.example.com`. Он не показывается в интерфейсе и не предназначен для получения писем.

Регистрация выполняется Edge Function с серверным Admin API: функция создаёт пользователя с `email_confirm: true`, поэтому подтверждающее письмо не отправляется. Затем браузер выполняет обычный вход через Supabase Auth. Публичный HTML никогда не получает service-role key.

Edge Function ограничивает регистрацию пятью попытками в час с одного IP. Это базовая защита; перед широкой публичной регистрацией стоит добавить CAPTCHA и мониторинг злоупотреблений.

## Однократная настройка владельцем проекта

### 1. Создать Supabase project

1. Откройте [Supabase](https://supabase.com/dashboard) и войдите в свой аккаунт.
2. Создайте новый проект, например `gpt-build-lab`.
3. Сохраните пароль базы данных в надёжном месте. Он не нужен в HTML и не должен попадать в GitHub.
4. Дождитесь завершения создания проекта.

### 2. Применить SQL-миграции

1. В Supabase откройте **SQL Editor**.
2. В GitHub откройте файл `supabase/migrations/202611210001_initial_schema.sql`, скопируйте весь SQL и выполните его.
3. Затем откройте `supabase/migrations/202611210002_username_accounts.sql`, скопируйте весь SQL и выполните его.
4. Убедитесь, что оба запроса завершились без ошибок.

Первый файл создаёт таблицы проектов и сборок. Второй добавляет профили пользователей. Порядок важен.

### 3. Настроить Supabase Auth

1. В Supabase откройте **Authentication → Providers → Email**.
2. Убедитесь, что Email provider включён. Он нужен для входа по внутреннему email/password.
3. Настройка **Confirm email** больше не управляет регистрацией через сайт: Edge Function создаёт подтверждённого пользователя через Admin API без отправки письма.
4. В разделе **Authentication → URL Configuration** укажите Site URL:
   `https://artemkinus-collab.github.io/GPT-Build-Lab/`
5. В Redirect URLs добавьте:
   `https://artemkinus-collab.github.io/GPT-Build-Lab/**`

### 4. Применить новую миграцию ограничения регистрации

1. Откройте **SQL Editor** в Supabase.
2. Откройте в GitHub файл `supabase/migrations/202611220001_signup_rate_limit.sql`.
3. Скопируйте весь SQL и выполните его один раз.
4. Не запускайте повторно старые миграции `202611210001` и `202611210002`, если таблицы уже созданы.

### 5. Развернуть Edge Function

1. В Supabase откройте **Edge Functions** и нажмите **Deploy a new function** / **Create function**.
2. Назовите функцию точно: `username-signup`.
3. В редакторе функции замените шаблон содержимым файла `supabase/functions/username-signup/index.ts` из GitHub.
4. Разверните функцию.
5. В настройках функции проверьте, что доступны системные переменные `SUPABASE_URL` и `SUPABASE_SERVICE_ROLE_KEY`. Supabase обычно предоставляет их Edge Functions автоматически. Если переменной service-role нет, добавьте её в **Edge Functions → Secrets** из раздела API Keys. Значение держите только в Supabase — не присылайте его в чат и не добавляйте в GitHub.

Функция публичная для вызова из формы, поэтому в `supabase/config.toml` для неё отключена JWT-проверка. Она самостоятельно проверяет Origin и применяет серверный лимит регистрации. Никогда не вставляйте service-role key в HTML или `web/supabase-config.js`.

### 4. Вставить публичные ключи в конфигурацию сайта

1. В Supabase откройте **Project Settings → API** (в некоторых версиях панели — **API Keys**).
2. Скопируйте **Project URL**.
3. Скопируйте публичный **anon / publishable key**. В зависимости от версии панели он может называться `anon` или `publishable`.
4. В GitHub откройте файл `web/supabase-config.js` и нажмите Edit.
5. Замените только два значения:

```js
window.GBL_SUPABASE_CONFIG = {
  url: "https://ВАШ_PROJECT_ID.supabase.co",
  anonKey: "ВАШ_ПУБЛИЧНЫЙ_ANON_ИЛИ_PUBLISHABLE_KEY"
};
```

6. Сохраните изменения через **Commit changes**.

Публичный anon/publishable key предназначен для браузерного клиента. Защиту обеспечивает RLS. **Никогда не вставляйте сюда** `service_role`, secret key, пароль базы данных или GitHub token.

### 7. Дождаться публикации и проверить

1. Откройте [GitHub Actions](https://github.com/artemkinus-collab/GPT-Build-Lab/actions) и дождитесь успешного Pages deployment.
2. Откройте сайт в приватной вкладке или обновите его без кэша.
3. Нажмите **Войти → Зарегистрироваться**.
4. Создайте тестовый аккаунт с уникальным именем и паролем не короче 8 символов.
5. После регистрации должен открыться dashboard, а в правом верхнем углу появиться иконка аккаунта.
6. Откройте меню, проверьте имя, перейдите в настройки и измените аватар.
7. Обновите страницу: сессия и аватар должны сохраниться.
8. Нажмите **Выйти** в меню аккаунта и убедитесь, что снова появилась кнопка входа.

## Ограничения текущей схемы

- Так как используется технический адрес без настоящей почты, самостоятельное восстановление забытого пароля пока не предусмотрено. Не теряйте пароль. Перед открытием регистрации широкой аудитории нужно решить вопрос восстановления доступа.
- Сейчас реализованы профиль и авторизация. Локальные проекты из браузера ещё не синхронизируются автоматически с таблицей `projects`.
- GitHub OAuth отложен; текущая форма использует имя пользователя и пароль.
- Для публичной регистрации рекомендуется добавить CAPTCHA/защиту от ботов и следить за лимитом Edge Function.
- Не создавайте таблицы профилей с публичным чтением. Оставьте включённым RLS и политики из миграции.
- Не публикуйте в репозитории резервные копии, содержащие секреты.

## Что ещё предстоит сделать

1. Облачная синхронизация проектов между устройствами.
2. Экран истории ZIP-сборок и безопасная выдача артефактов.
3. Процесс восстановления аккаунта, не требующий доступа к несуществующему email.
4. GitHub OAuth как дополнительный способ входа, если он понадобится.
5. Ограничение частоты запросов и антибот-защита перед массовым запуском.
